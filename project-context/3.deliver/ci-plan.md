# CI Plan — OnboardFlow AI

Generated by: `@devops.eng`  
Phase: Deliver  
Date: 2026-06-07  
Status: Approved by Agentic Architect

## 1. Purpose

This document defines the first continuous integration plan for OnboardFlow AI.

The CI goal is to catch normal regressions quickly on pull requests while keeping the default path deterministic, provider-free, and inexpensive.

## 2. CI Principles

- Use repository lock files.
- Keep default CI fast and deterministic.
- Do not call live Gemini, CrewAI AMP, email, service desk, HRIS, IAM, LMS, chat, or provisioning systems.
- Separate live LLM/provider validation into an explicit manual workflow later.
- Fail on backend test, migration, compile, frontend test, build, or formatting errors.
- Keep secrets out of default CI.

## 3. Current Repository Findings

Confirmed:

- No `.github/workflows/` workflow exists yet.
- Backend uses `uv` and `backend/uv.lock`.
- Backend supports deterministic mode through `ONBOARDFLOW_FLOW_MODE=deterministic`.
- Backend AMP tracing is opt-in through `CREWAI_AMP_TRACING=false`.
- Frontend uses npm and `frontend/package-lock.json`.
- Frontend supports `npm test -- --watch=false`, `npm run build`, and `npx prettier --check .`.
- Backend supports `uv run pytest`, `uv run python -m compileall src tests`, and `uv run alembic upgrade head`.

Known limits:

- There is no backend lint script yet.
- There is no frontend lint script yet.
- There is no browser automation for the full `Aprovar e simular envios` path yet.
- Frontend API base URL is static in Angular environment configuration.

## 4. Recommended Workflow Shape

Create one default PR workflow later:

```text
.github/workflows/ci.yml
```

Recommended triggers:

```text
pull_request
push to main
workflow_dispatch
```

Recommended jobs:

- `backend`
- `frontend`

The jobs can run in parallel because the frontend tests mock API boundaries and backend tests use deterministic local execution.

## 5. Backend CI Job

Runtime:

- Ubuntu runner.
- Python `3.12`.
- `uv` installed through an official/setup action or pinned installer.

Environment:

```text
ONBOARDFLOW_FLOW_MODE=deterministic
CREWAI_AMP_TRACING=false
DATABASE_URL=sqlite:///./ci-onboardflow.db
API_CORS_ORIGINS=http://localhost:4200,http://127.0.0.1:4200
```

Commands:

```text
cd backend
uv sync --all-extras --dev
uv run alembic upgrade head
uv run pytest
uv run python -m compileall src tests
```

Acceptance:

- Dependencies install from `uv.lock`.
- Alembic migrations apply cleanly against SQLite.
- All backend tests pass.
- Python source and tests compile.
- No live LLM credentials are required.

## 6. Frontend CI Job

Runtime:

- Ubuntu runner.
- Node `24`, matching the Dev Container.
- npm from the project/package-manager toolchain where available.

Commands:

```text
cd frontend
npm ci
npm test -- --watch=false
npm run build
npx prettier --check .
```

Acceptance:

- Dependencies install from `package-lock.json`.
- Angular/Vitest tests pass.
- Production build passes without budget warnings.
- Prettier check passes.
- No backend server is required for default frontend CI.

## 7. Secrets Policy

Default CI must not define or require:

```text
GEMINI_API_KEY
CREWAI_API_KEY
OPENAI_API_KEY
CREWAI AMP login/session credentials
email provider credentials
service desk credentials
```

If a workflow ever needs live provider validation, it must be separate, manual, and explicitly named.

## 8. Future Manual Live Provider Workflow

Create only after the default CI is stable and the Agentic Architect approves live validation.

Candidate file:

```text
.github/workflows/live-crewai-smoke.yml
```

Recommended trigger:

```text
workflow_dispatch
```

Required secrets:

```text
GEMINI_API_KEY
```

Optional secrets or setup:

```text
CREWAI_API_KEY or CrewAI AMP auth mechanism, if supported by the chosen runner setup
```

Expected behavior:

- Run one live CrewAI generate or refine smoke.
- Publish or verify AMP trace only when tracing is intentionally enabled.
- Report run id and high-level result without exposing employee PII or secrets.

## 9. Failure Conditions

Default CI should fail if:

- `uv sync --all-extras --dev` fails.
- Alembic upgrade fails.
- Backend tests fail.
- Python compileall fails.
- `npm ci` fails.
- Frontend tests fail.
- Angular production build fails or produces budget warnings as errors if configured by Angular.
- Prettier check fails.

Default CI should not fail because:

- Gemini credentials are absent.
- CrewAI AMP is not logged in.
- External email, service desk, HRIS, IAM, LMS, or chat systems are unreachable.

## 10. Implementation Notes

Recommended first implementation after this plan is approved:

- Add `.github/workflows/ci.yml`.
- Use separate backend and frontend jobs.
- Cache dependencies only after the first working workflow is confirmed, to keep the initial setup easier to debug.
- Keep CI logs free of secrets and large generated artifacts.

Do not add:

- Deployment jobs.
- Docker build jobs.
- Kubernetes, ECS, Redis, PostgreSQL, or managed cloud dependencies.
- Live LLM smoke in default CI.

## 11. Acceptance Criteria

This CI plan is accepted when the Agentic Architect confirms:

- Default CI should be deterministic and provider-free.
- Backend and frontend jobs should run independently.
- The listed commands are sufficient for the first CI gate.
- Live CrewAI/Gemini validation should remain a later manual workflow.
- Adding `.github/workflows/ci.yml` is authorized as the next Delivery implementation step.
