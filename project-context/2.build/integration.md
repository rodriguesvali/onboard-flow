## 1. Scope Implemented

Connected the approved Angular + PrimeNG Generate Onboarding Plan workflow to the Python FastAPI backend.

Included:

- Replaced the mocked Angular `OnboardingRunService` with real `HttpClient` calls.
- Added frontend API base URL configuration through `frontend/src/environments/environment.ts`.
- Added `provideHttpClient()` to the standalone Angular application configuration.
- Wired `POST /api/onboarding/generate` for run creation.
- Wired `GET /api/onboarding/runs/{runId}` with polling until the backend returns `done` or `error`.
- Wired `POST /api/onboarding/runs/{runId}/refine` from the existing `Solicitar ajustes` review action.
- Preserved frontend-only approval behavior for `Aprovar plano`; no backend approval persistence was added.
- Preserved server-side-only CrewAI/Gemini details; no provider credentials or CrewAI internals were added to the frontend.

Excluded:

- Real HRIS, ITSM, IAM, LMS, email, chat, payroll, SSO/RBAC, analytics, or external provisioning integrations.
- Backend-persisted approval workflow.
- New authentication or mock-user propagation from the frontend.
- CrewAI Knowledge integration.

## 3. Contract Decisions

- Frontend request payload remains camelCase and matches backend `EmployeeOnboardingInput` aliases.
- Backend API base URL defaults to `http://localhost:8000`.
- FastAPI CORS allows `http://localhost:4200` and `http://127.0.0.1:4200` through `API_CORS_ORIGINS`.
- `startRun` maps directly to `POST /api/onboarding/generate`.
- `pollRunStatus` checks `GET /api/onboarding/runs/{runId}` every 2 seconds and times out after 180 seconds.
- `done` responses require `result` before the UI transitions to the results view.
- `error` responses use `errorMessage` when present, then `message`.
- The existing `Solicitar ajustes` action now sends the instruction to backend refinement and updates the visible plan with the returned revision.
- `Aprovar plano` remains session-local and explicitly does not send communications or trigger external systems.
